# 云开发

后台用微信云开发（云函数加云数据库）。注意不是「微信云托管」：云托管是部署容器服务的，要 Dockerfile 和端口，这个项目用不到，不要在云托管里发布这个仓库。

小程序端只调一个云函数 `api`，数据库集合不对小程序端开放；另有一个定时云函数 `remind` 负责发「活动开始提醒」。

```
cloudfunctions/
  api/       接口：会员、活动、报名、提醒、补给计划
  remind/    定时任务：报名开放后发订阅消息（每 5 分钟检查一次）
```

小程序端的入口是 `miniprogram/utils/cloud.js`（调用）、`utils/store.js`（会员、报名、提醒、计划）、`utils/events.js`（活动）。`miniprogram/config.js` 的 `cloudEnv` 留空时不走云开发，只存本机。

## 部署步骤

前提：小程序已用正式 AppID 注册。手机号一键注册用的是「手机号快速验证组件」，只对**已认证的非个人主体**开放，每次成功调用收费 0.03 元（每个小程序有 1000 次体验额度），以微信官方文档现行说明为准。

1. **AppID**：`project.config.json` 里已经填了正式 AppID。用这个小程序的管理员或开发者微信登录开发者工具。
2. **开通云开发**：在微信开发者工具里点左上角「云开发」，创建环境，记下环境 ID。
3. **环境 ID**：`miniprogram/config.js` 的 `cloudEnv` 已经填好（`cloud1-d1g1u97accc6092f6`）。
4. **建集合**：在云开发控制台的数据库里新建五个集合：`members`、`events`、`signups`、`reminders`、`plans`。权限都设成「所有用户不可读写」（只有云函数能读写）。另有一个 `counters` 集合（存下一个会员编号）不用手动建，第一位会员注册时云函数会自己建；建好后可以在控制台把它的权限也改成「所有用户不可读写」。
5. **上传云函数**：在开发者工具的文件树里右键 `cloudfunctions/api` 和 `cloudfunctions/remind`，各选一次「上传并部署：云端安装依赖」。`remind` 再右键选「上传触发器」。云函数默认的超时时间很短，在云开发控制台的云函数配置里把 `remind` 调到 60 秒、`api` 调到 10 秒。
6. **订阅消息模板**：已申请公共模板「活动动态通知」，模板 ID 已填在 `miniprogram/config.js` 的 `subscribeTemplateId`，五个字段已对到 `cloudfunctions/remind/template.js`。改了这个文件后要重新上传 `remind`。
7. **录入活动**：按下面的格式在 `events` 集合里添加活动。没有活动时「活动」页的「即将开始」显示「敬请期待」，录入后自动出现，不用改代码也不用重新发版。

云调用的权限（`phonenumber.getPhoneNumber`、`subscribeMessage.send`）已经写在两个云函数各自的 `config.json` 里，上传时生效，有约 10 分钟缓存。

## 资源放到云存储

图片、视频、字体不打进小程序包，放在同一个云环境的云存储里（自带 CDN，基础套餐含 5GB CDN 流量）。**现在已经传好**，`miniprogram/config.js` 的 `assetBase` 填的就是云存储的地址。下面的步骤是以后换素材或换环境时用的。

1. 在仓库根目录运行 `npm run cdn`。它把小程序实际用到的 38 个文件（约 7MB）挑到 `out/cdn/assets/` 里，没用到的 720p 原片、多余的字体不带上。
2. 打开云开发控制台的「存储」，把 `out/cdn/` 里的 `assets` 文件夹整个上传到根目录，保持 `assets/` 这一层目录不变。
3. 在「存储」的权限设置里选「所有用户可读，仅创建者可读写」，否则用户的手机加载不了。
4. 点开任意一个上传好的文件，复制它的下载地址，形如 `https://7370-xxxx-1300000000.tcb.qcloud.la/assets/logo/avatar.svg`。取 `/assets/` 前面的那一段，填到 `miniprogram/config.js` 的 `assetBase`，例如 `assetBase: 'https://7370-xxxx-1300000000.tcb.qcloud.la'`。地址后面如果带 `?sign=...` 之类的参数，不要带上。
5. 重新编译，关掉「不校验合法域名」再看一遍：图片、视频、数字字体都应该正常。

图片和视频用的是 `image`、`video` 组件，不需要把这个域名加进小程序后台的服务器域名（那里只管 `wx.request`、上传、下载、WebSocket）。

数字字体的加载单独处理（`miniprogram/utils/fonts.js`）。`wx.loadFontFace` 用 https 地址时要求服务器允许跨域；云存储本身允许，但它前面的 CDN 会把不带跨域许可的响应缓存下来，所以直接用地址加载时好时坏。现在的做法是用 `wx.cloud.downloadFile` 把字体下到本机，读成 Data URL 再加载，不经过跨域检查，也不用配下载域名；下过一次就存在本机。这条路失败时退回用地址加载，再失败就是系统字体，不影响使用。

以后换图：替换云存储里的同名文件即可；新增了资源就重新跑一次 `npm run cdn`，把新增的文件传上去。

## 隐私和协议

- 《用户协议》《隐私政策》的正文在 `reference/content/legal.json`，是按小程序实际收集的信息起草的初稿，**上线前请法务审阅**。文件开头 `fill` 里的四项填一次，正文里会自动替换：四项都已填好。改完运行 `npm run content`。
- 微信要求在小程序后台配置《用户隐私保护指引》（「账号设置 → 服务内容声明 → 用户隐私保护指引」），只有在里面声明过的信息才能调用对应的接口。本小程序现在实际用到的只有**手机号**（用途：会员注册）。隐私政策里另外预留了昵称头像、收货地址、位置、日历（仅写入）、剪切板、相册（仅写入）六项，供后续功能使用，后台的指引里已一并声明。提审时这份指引要和 `legal.json` 里的隐私政策一致。
- 注册按钮是 `open-type="getPhoneNumber|agreePrivacyAuthorization"`：用户勾选协议后点它，既向微信表明已同意隐私政策，又发起手机号授权。
- 以后如果新增收集的信息（头像昵称、位置等），三处要一起改：`legal.json`、小程序后台的指引、对应的授权流程。

会员编号按注册先后发，6 位数字，从 100001 起（`api` 里的 `nextMemberNo`）。没有编号的会员（规则定下来之前注册的，或注册时取号失败的）下次进入小程序时补发，页面上暂时显示「—」。

注册送 500 积分（`api` 里的 `WELCOME_POINTS`；页面上的说法在 `reference/content/member.json` 和 `messages.json`，要改一起改）。没领过的老会员下次进入小程序时补送一次，用 `welcomeBonus` 标记防止重复送。报名用积分已定，见下面「用积分报名」；积分怎么兑换还没定。要给某个会员加减积分，用运营后台的「积分」，它会同时改积分和记一条记录（记录里的 `by` 是操作的管理员）。不要直接在控制台改 `points`，那样积分页的记录里没有这一笔。

昵称由用户在会员页自己填（`setNickname` 接口），最多 20 个字。输入框用的是微信的昵称键盘，内容安全由微信的组件检测。

小程序端拿到的手机号是打码后的（`138****1234`），完整手机号只存在 `members` 里。

## 运营后台

小程序里有一个只有管理员能看到的「运营后台」（「我的」页最下面一行），能做这几件事：

- **活动**：新建、编辑、上架、下架。表单里的字段就是下面「活动怎么填」那张表。头图在表单里选图片，会传到云存储的 `events/` 目录。上架着、还没开始的活动可以点「通知订阅的人」，见下面的「新活动通知」。
- **往期**：活动页「往期」里的赞助赛事。填年份、名称、英文名或副标题，选一张照片。保存后小程序里马上能看到，不用重新发版。年份新的排在前面，同一年里新加的排在前面。照片传到云存储的 `events/` 目录。
- **公告**：填标题和内容，打开开关后保存。每位用户下次打开小程序时弹一次；改了再保存算新的一条，会再弹一次；关掉开关保存就不再弹。
- **积分**：按手机号或会员编号找到会员，加或减积分，写上原因。会员在自己的积分页能看到这一笔。减的时候积分不够会失败，不会减成负数。

**怎么把某个人设成管理员**：

1. 让他先在小程序里登录成为会员。
2. 打开云开发控制台的数据库，进 `members` 集合，找到他那条记录（可以按 `phone` 手机号找）。
3. 点「添加字段」，字段名 `admin`，类型选 boolean，值选 `true`，保存。
4. 让他完全关掉小程序再打开，「我的」页最下面会多出「运营后台」。

取消管理员：把 `admin` 改成 `false` 或删掉这个字段。

权限是在云函数里检查的（`api` 里 `admin` 开头的接口都先过 `requireAdmin`），不是管理员的人就算拿到页面地址也调不通。表单里的时间按操作人手机所在的时区理解，运营在国内操作就是北京时间。

公告存在 `settings` 集合里 `_id` 为 `notice` 的那条记录上，集合第一次保存公告时由云函数自己建。

## 电脑端后台

`web-admin/index.html` 是运营后台的网页版，功能和小程序里的一样（活动、公告、积分），在电脑浏览器里用，活动是表格，头图直接从电脑选。

### 第一次部署

都在微信开发者工具的「云开发」控制台里做。

1. **开通静态网站**。控制台「更多 → 静态网站」，点开通。只有按量付费的环境能开通。开通后会得到一个默认域名，记下来。
2. **上传网页**。在静态网站的文件管理里，把仓库里的 `web-admin/index.html` 传到根目录。以后网页有改动，重新传这一个文件。
3. **打开未登录访问**。控制台「设置 → 权限设置」，打开「未登录访问」。网页没有微信身份，不开这个调不到云函数。
4. **改云函数的权限**。云函数的权限设置选「安全规则」，填：

   ```json
   {
     "*": { "invoke": "auth != null && auth.loginType != 'ANONYMOUS'" },
     "api": { "invoke": true }
   }
   ```

   输入框里原来有一段默认规则，整段删掉再贴上面这段，不要接在后面：里面只能有一对最外层的大括号。`"*"` 那一行就是原来的默认规则，原样留着。

   意思是只有 `api` 这一个函数允许没有微信身份的调用，别的函数照旧。
5. **重新上传 `api` 云函数**（登录码、登录凭证、传图的逻辑在里面）。
6. 把第 1 步的默认域名填到 `miniprogram/config.js` 的 `webAdminUrl`（带 `https://`）。这一步只是让小程序里能显示和复制网址，不填也能用。

### 怎么登录

1. 电脑浏览器打开静态网站的默认域名。
2. 手机打开小程序，「我的 → 运营后台 → 电脑端」，点「获取登录码」。
3. 把 12 位数字填到网页上。登录码 5 分钟内有效，只能用一次；登录一次管 12 小时，到时间重新取码登录。

### 安全上是怎么做的

- 打开未登录访问以后，`api` 对公网可见，任何人都能调它。所以没有微信身份的调用只认两种：用登录码登录（`webLogin`），和带着登录凭证调后台接口（`WEB_ACTIONS` 里列的那几个）。小程序用户的接口（注册、报名、积分页等）没有微信身份一律调不通。
- 登录码只能在小程序里由管理员取。12 位数字，5 分钟内有效，用一次就作废。
- 输错登录码不锁定、不记数。网页没有微信身份，云函数分不清是谁在输；要是「输错几次就锁」，任何人乱输几次就能把所有管理员挡在外面。防猜靠的是位数：一万亿种里只有刚取的那一个是对的，又只管 5 分钟。输错也不往库里写任何东西。
- 登录码和登录凭证在库里只存摘要（`admin_web` 集合），库里的数据被人看到也登录不了。
- 带着凭证的每次调用仍然检查这个人是不是管理员：撤掉 `admin: true`，他已经登录的网页马上用不了。
- 传头图只收 JPEG、PNG、WebP，最大 2MB，由云函数写进云存储，网页不直接碰云存储。数据库和存储的权限不用为网页改动。

## 活动怎么填

平时在运营后台里填。下面是 `events` 集合的字段，也可以直接在云开发控制台改，时间字段的类型选「date」。

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | string | `赛事`、`试用装`、`抽奖`，决定卡片样式 |
| `title` | string | 活动名称 |
| `status` | string | `published` 才会显示；其他值（如 `draft`）不显示 |
| `date` | date | 活动日期和时间。过了一天以后自动从「即将开始」里消失 |
| `city`、`venue` | string | 城市、场地 |
| `quota` | number | 名额上限。不填就不限 |
| `quotaText` | string | 名额的显示文字（如「限 200 份」）。不填就显示 `quota` 的数字 |
| `signupStart`、`signupEnd` | date | 报名起止时间 |
| `memberSignupStart` | date | 会员提前报名的开始时间。填了卡片上才显示「会员优先报名」，提醒也按这个时间发 |
| `drawAt` | date | 开奖时间（抽奖用） |
| `cover` | string | 头图。云存储的 fileID（`cloud://...`）或 https 地址；不填用默认配图 |
| `intro` | string | 活动介绍 |
| `signupCount` | number | 已报名人数，由云函数维护，不用手填 |

活动没有提供的项，页面上不显示，不会留方括号占位。

**报名规则目前的做法**：报名要先是会员；从 `memberSignupStart`（没填就用 `signupStart`）到 `signupEnd` 之间可以报；有 `quota` 时不超额；同一个人同一场只算一次。已报名人数 `signupCount` 不管限不限名额都记，名额是先占后写报名记录，中途出错时只会偏多不会偏少，最坏情况是空出一个名额，不会超额。在运营后台保存带名额的活动时，如果这个数比报名记录少，会补到和记录一样多（只补不减，免得抹掉正在报名的人占的名额）。会员优先报名提前多久、试用装和抽奖怎么领怎么开（`docs/04-open-items.md`）定了以后，改 `api/index.js` 的 `signup`。

## 订阅消息的字段

用公共模板「活动动态通知」，五个关键词：活动名称（`thing1`）、开始时间（`time7`）、温馨提示（`thing4`）、截止时间（`time3`）、活动地点（`thing8`）。`remind/template.js` 开头的 `FIELDS` 把它们对应到活动数据：活动名称、活动开始的时间、「报名已开放」、报名截止的时间、城市加场地。五个字段发送时都必须有值：活动没填报名截止时间时用活动开始时间顶上，没填城市和场地时写「详见活动详情」。所以录活动时最好把 `signupEnd`、`city`、`venue` 都填上。以后换模板或改关键词，按新模板「详细内容」里的字段名改 `FIELDS`。`miniprogramState` 上线后用 `formal`，调试时改成 `developer` 或 `trial`。

提醒的流程：用户点「提醒我」→ 调起订阅授权 → 同意后在 `reminders` 里登记 → 报名开放后 `remind` 先把记录标成 `sent: true`、`status: 'sending'`（领取），再发送，发完记成 `sent` 或 `failed`。一次授权只能发一条，所以宁可漏发不重发：发送失败（用户取消订阅等）会把原因记在 `error` 里，不重试；如果执行中途中断，记录会停在 `sending`，也不会自动重发，可以在数据库里按 `status` 查出来。一次执行最多发 300 条，多出来的下一次接着发。

## 新活动通知

用户在活动页最下面点「通知我」，同意订阅授权后在 `news_subs` 里登记（每人一条记录）。运营在后台对某场活动点「通知订阅的人」，订阅着的人各收到一条「活动动态通知」，温馨提示一栏写「新活动上线」，点开进这场活动的详情页。

要知道的几件事：

- **点一次只管一条**。这是微信一次性订阅消息的规则。收到一条之后，用户那边的按钮回到「通知我」，要再点一次才有下一条。所以后台显示的订阅人数会随着每次通知减少。
- **每场活动只能通知一次**。重复通知会把大家的额度白白用掉。
- **发给点「通知」那一刻订阅着的人**。每次登记有一个自己的编号（活动上的 `notifyId`），点的时候就把这些人划给这次登记（订阅记录上的 `job` 和 `eventId`），每个人只会划给一次。之后才订阅的人已经能在活动页看到这场活动，额度留给下一场。上一场刚把人划走、还没有新的人订阅时，下一场会提示「还没有人订阅新活动通知」，这场的机会还在。
- **不是马上发出**。点「通知」只是在活动上登记（`notifyStatus: 'pending'`），由 `remind` 云函数每 5 分钟发一批，一次最多 300 条，人多时分几次发完。发完活动上记成 `done`，后台显示「已通知 N 人」。发不出去的（用户关了订阅消息等）记在 `notifyFailed` 里，不重试。
- 登记之后把活动下架，定时任务下一次执行时（5 分钟内）会停掉这场通知，没发到的人放回去留给下一场。那时还没开始发的，当作没通知过，重新上架后可以再通知；已经发出去一部分的，这场到此为止。下架后很快又上架回来、定时任务还没跑到的，照常发。
- 活动日期过了还没发完的，不再发，没发到的人同样放回去。
- 发送中途数据库出错，这场保持发送中，下一次执行接着发。
- 点「通知」时提示网络异常、列表上却显示「通知发送中」：登记做到一半断了。不用管，两分钟后定时任务会撤掉这次登记、把人放回去，之后可以重新点「通知」。
- 内容只能是活动信息。微信运营规范不允许用订阅消息发营销内容，也不允许发和用户订阅时理解的不一样的东西。

这个功能要重新上传 `api` 和 `remind` 两个云函数。

## 用积分报名

每场活动可以设「报名所需积分」（活动上的 `cost`，不填或填 0 是不用积分）和「联系方式」（`contact`，显示在活动详情页的「报名须知」里）。

- **报名**：积分不够报不了。占名额、扣积分、写报名记录在一个数据库事务里，要么都做成要么都没做，不会扣了积分却没报上。取消报名的删记录、放名额、退积分、留消息也是一个事务，中途出错再点一次就行。扣的这一笔会出现在会员的积分记录里。
- **会员不能自己取消**。详情页上写着要调整请联系我们，所以联系方式最好填上。
- **运营取消某个人的报名**：后台活动列表点「名单」，在名单里点「取消报名」。记录删掉、名额放回、积分退回，对方会收到通知。取消之后这个人可以重新报名。
- **取消整场活动**：名单页最下面的「取消整场活动」。活动下架并标上「已取消」，所有报名的人退积分、收通知。一次处理 40 人，人多时页面会自动接着处理到完；提示「还有人没处理完」时再点一次。
- **通知怎么到**：一定会有一条站内消息（`inbox`），对方下次打开小程序时弹出来。报名时同意了订阅消息的，另外收到一条微信的「活动动态通知」。微信不允许把订阅当成报名的条件，所以报名时只是问一次，拒绝了也照样能报。
- **名单里有什么**：昵称、会员编号、完整手机号、报名时间、用了多少积分。小程序里可以拨打和复制，电脑端可以导出表格。
- **加到往期**：活动列表上的「加到往期」把这场活动的名称、年份、头图抄进往期赞助赛事，之后在「往期」里可以再改。
- **发公告**：活动列表上的「发公告」把这场活动的名称和时间地点填进公告并打开，会员进小程序时弹一次。

`api` 这次多了一个云调用权限 `subscribeMessage.send`（写在 `api/config.json`），并带了一份 `template.js`，它和 `remind/template.js` 必须一模一样（`npm test` 会核对），改一处要把另一处也改了。要重新上传 `api`。
